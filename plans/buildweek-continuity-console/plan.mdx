<Callout tone="decision">
The BuildWeek deliverable is a **Verified Recovery Console**. Its load-bearing extension is deterministic reconciliation: transcript events, explicit tool results, and current Git state become a versioned `RecoveryBrief` that says what is observed, what is inferred, what remains unknown, and what the next agent may safely do. The console is the product experience for that proof; the evidence contract is the technical center.
</Callout>

## Product thesis

**When a coding agent dies, Agent Ledger separates what the session recorded from what the repository proves now, then hands the next agent a safe local continuation brief.**

Initial audience: developers using a local Claude Code transcript as the interrupted source and handing work to any next coding-agent session through files and a vendor-neutral prompt. The source claim remains Claude Code only until another local format has its own inspected adapter and fixtures.

## Why this scope

The official BuildWeek rules evaluate pre-existing projects only on work added after the July 13 start. Commit `61dd0c6` (2026-07-14) is the first eligible functional extension: it added deterministic packet extraction/rendering and tests. The new slice must be visibly and technically more than a wrapper around that packet.

## Kingfisher Move: flight recorder plus incident brief

**TL;DR:** Borrow a flight recorder's immutable evidence and an incident brief's action discipline, while rejecting black-box hardware, automatic control, and response bureaucracy.

| Layer | Answer |
|---|---|
| Source phenomenon | Flight recorders preserve event evidence; incident command separates situation facts from response actions. |
| What it computes | Local artifacts + current repository state → traceable observations, contradictions, uncertainty, and ordered safe actions. |
| Source baggage to reject | Specialized hardware, centralized operations, pagers, approval chains, and postmortem ceremony. |
| Transferable principle | Recovery begins by reconciling evidence before action. |
| Target implementation | Versioned RecoveryBrief, stable evidence locators, readiness checks, and a guarded continuation prompt. |
| Existing wheels | Existing transcript parser and resume packet, Git CLI, Pydantic, Typer, FastAPI. |
| Hybrid advantage | More portable than a vendor's native resume and more trustworthy than an unconstrained summary. |
| Wrong-if | The brief cannot expose one meaningful difference between recorded claims and current repository truth. |
| Next experiment | The sanitized crash fixture must turn an unverified test command into an explicit `unknown` verification state and a safe next action. |

**Status:** candidate

## Hard-to-reverse decisions

<Callout tone="decision">
`ResumePacket` v1 stays backward-compatible and transcript-centric. A separate `RecoveryBrief` v1 is the public reconciliation wire format because it combines multiple evidence sources and has different lifecycle semantics. Observations use categorical certainty (`observed`, `inferred`); unresolved claims are separate `Uncertainty` records rather than invented confidence percentages. Schema changes require a version bump and golden compatibility tests.
</Callout>

<Callout tone="decision">
Transcript content is untrusted data, never executable instruction. Only application-authored templates may become `ContinuationAction.instruction`; transcript TODOs, assistant prose, commands, and paths remain quoted evidence. The trusted repository comes only from explicit `--repo PATH` input or the invocation directory. Touched paths are normalized repo-relative paths; escapes, symlinks outside the repo, absolute paths, pathspec options, and traversal are rejected before fixed read-only Git calls.
</Callout>

<Callout tone="decision">
The `RecoveryBrief` envelope is provider-neutral, but v1 ships only one declared source adapter: `claude-code-jsonl@1`. Evidence IDs are deterministic hashes of source kind + adapter version + redacted locator; canonical JSON uses sorted keys and stable list ordering. Another provider requires a separate inspected adapter and fixtures, never a heuristic reuse of the Claude parser.
</Callout>

<Callout tone="decision">
Do not add React, Node, authentication accounts, or a second product service. The first console is FastAPI plus shipped HTML/CSS/JavaScript assets. Every console run uses an ephemeral capability token, strict Host/Origin checks, no CORS, `Cache-Control: no-store`, CSP with `frame-ancestors 'none'`, and local assets only. Distinctiveness comes from the recovery interaction and evidence ledger, not frontend infrastructure.
</Callout>

Evidence locators may identify a transcript line, tool-use/tool-result pair, Git `HEAD`, branch, or worktree-status snapshot. A recorded attempt, a recorded tool result, and a current difference from `HEAD` are distinct observations; the system never claims that the interrupted session caused the current difference. Exported JSON must not include an absolute home path or raw private transcript excerpt by default. `generated_at` is supplied by an injectable clock so fixtures and golden output remain deterministic.

## Product flow

```text
sanitized/local transcript ─┐
explicit tool results ──────┼─> RecoveryBrief v1 ─> console ─> copy safe prompt
current Git read-only state ┘       facts / gaps / readiness / next actions
```

The single screen answers four questions in order:

1. **What stopped?** Ending, intent, last activity, and touched files.
2. **What can I trust?** Observed facts with stable evidence locators.
3. **What differs or remains unknown now?** Current `HEAD`, dirty state, touched-file state relative to `HEAD`, and commands without explicit successful results.
4. **How do I resume safely?** Three evidence-linked actions and a vendor-neutral prompt that tells the next agent to verify before editing.

The visual direction is a compact flight-recorder strip crossed with an editorial incident brief: graphite, warm paper, red/amber/green used only for readiness, tabular evidence locators, and one dominant “Copy continuation brief” action. No vendor logos, decorative dashboard charts, external fonts, or decorative motion. Evidence highlighting must work with keyboard and reduced motion.

## Local interface contracts

`agent-ledger recover --session ID --repo PATH --format json|prompt` emits one canonical artifact. `agent-ledger recover --session ID --repo PATH --open` starts the capability-token console for that same brief and cleans up on exit. `agent-ledger demo [--no-open] [--smoke] [--port 8680]` creates a disposable synthetic repository, invokes the same assembly/UI path, and in smoke mode starts, fetches, verifies, stops, and deletes its temporary directory.

## Acceptance tests

1. **Evidence integrity:** every displayed observation, check, and action references an existing EvidenceRef; orphan or dangling IDs fail validation.
2. **Truth separation:** “attempt recorded,” “tool result recorded,” and “currently differs from HEAD” are separate claims. A Bash invocation without a conservatively parsed successful result is `unknown`, never “verified”; no current difference is causally attributed to the interrupted session.
3. **Repository boundary:** recovery accepts only explicit `--repo` or invocation cwd. Absolute/transverse touched paths, symlink escapes, leading-dash pathspecs, and transcript-supplied repository paths are rejected and never reach Git argv.
4. **Current readiness:** unavailable Git, detached HEAD, dirty worktree, deleted touched file, and touched-file state relative to `HEAD` each yield a deterministic named state. Commit-time freshness inference is deferred.
5. **No execution or prompt injection:** destructive shell text, imperative TODOs, and prompt-injection prose cause zero transcript-derived subprocess calls and never become `ContinuationAction.instruction`; tests assert exact Git argv and fixed action templates.
6. **Privacy/server boundary:** default JSON and prompt contain no absolute home path, credential-like fixture content, or raw transcript excerpt. The console requires an ephemeral token, loopback + strict Host/Origin, no CORS, no-store, CSP/anti-framing, local assets, and escaped text.
7. **Determinism:** fixed transcript + fixed Git snapshot + injected clock produces byte-identical canonical JSON and prompt output.
8. **Backward compatibility:** current `agent-ledger resume` golden output and all 45 baseline tests remain green; no ledger migration occurs.
9. **Runnable product:** a wheel installed into a disposable environment can execute `agent-ledger demo --no-open --smoke` and fetch the token-protected `/`, `/api/recovery`, and `/api/prompt` successfully before clean shutdown.
10. **Interface quality:** desktop 1440px and narrow 390px screenshots, full keyboard path, visible focus, contrast, reduced motion, and copy-action feedback are inspected after implementation. The screenshot audit begins only after a real console exists.
11. **Project gates:** Ruff format/check, MyPy strict, PyTest with ≥80% total and touched-module coverage, property tests for malformed JSONL, `uv build`, and the built-wheel smoke test pass.

## Failure modes and stop rules

<Callout tone="risk">
**Platform absorption:** Claude Code, Gemini CLI, Cursor, and other tools already resume their own sessions. If the demo looks like a prettier session history, the idea loses. Stop and cut visual polish until the proof layer visibly exposes a contradiction or unknown that native resume does not.
</Callout>

<Callout tone="risk">
**Generic-AI sameness:** no summarization model is part of the winning slice. Every claim in the interface must originate in deterministic parsing, explicit tool results, or Git. If an item cannot cite evidence, it belongs under uncertainty or recommendation.
</Callout>

<Callout tone="risk">
**Weak BuildWeek evidence:** do not present pre–July 13 M0–M3.a as judged work. The submission evidence starts from baseline `5baaf67`, identifies eligible functionality by commit, records the implementation Codex session ID, and shows the exact new files and tests.
</Callout>

<Callout tone="risk">
**Overbuilding:** build order is source-shape recon → recovery model → path/server safety tests → canonical JSON/prompt → demo fixture → filmed console path → video. General `serve`, Markdown, commit-time heuristics, background behavior, and broad visual polish remain deferred. If the deterministic model and demo fixture are not green before console work begins, do not start the console.
</Callout>

<Callout tone="risk">
**Privacy and injection:** the public repo and video use only synthetic data. Real transcript packets are never committed, uploaded, logged, or sent to a cloud model. Transcript-derived HTML is escaped; transcript imperatives never become actions; trusted repository selection and path containment happen before Git; and the capability-token server exposes no arbitrary local path.
</Callout>
