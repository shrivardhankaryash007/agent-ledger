# Recommendation

Build one closed recovery loop, not a broader agent dashboard. An operator starts Agent Ledger against a repository they explicitly trust, sees recent Claude Code and Codex sessions, opens an interrupted session, reconciles recorded activity with current Git truth, attaches a receipt from an explicit owner-selected verification command, and exports one portable handoff package.

The slice is complete when the current real Codex session can be discovered without exposing raw transcript content, its unmatched tool call is shown as unknown, repository-contained absolute paths reconcile safely, an explicit owner-supplied command produces a freshness-aware process receipt, and the browser downloads a canonical package containing the brief, safe prompt, receipt, and checksum manifest.

## Product contract

The operator flow is:

1. Run `agent-ledger console --repo PATH`. The CLI resolves one canonical trusted Git root before the server starts.
2. The Recovery Inbox discovers bounded recent candidates from configured Claude Code and Codex roots. A candidate appears only when its adapter-provided working-directory evidence canonically resolves to the same Git root as the trusted repository; unbound or mismatched sessions are excluded from the console and reported only as aggregate exclusion counts.
3. Selecting a candidate invokes its declared adapter, assembles `RecoveryBrief` v1 against the trusted repository, and shows recorded facts, present Git facts, and unknowns as separate claims.
4. If a current command receipt is missing, stale, failed, or timed out, the UI explains the exact local CLI invocation shape. Only a command explicitly supplied by the owner after `--` may run; `shell=False`, the trusted repository is the working directory, and transcript commands are never inputs.
5. Every process attempt produces `RecoveryReceipt` v1. The UI says only what was observed—such as “command exited 0”—and calls the receipt current only while the content-sensitive repository fingerprint and selected brief digest still match.
6. A single download returns `RecoveryPackage` v1: canonical brief, guarded prompt, latest receipt with applicability, and component checksums. Export remains available in unknown/failed/stale states and carries that status unmistakably.

The browser is deliberately outside the command-execution boundary: all routes remain GET-only. It may display receipts and package artifacts, but it cannot start a subprocess, accept arbitrary filesystem paths, mutate the repository, or manufacture a verification claim.

## Kingfisher transfer

| Transfer | Recovery Loop translation |
|---|---|
| Flight recorder | Preserve ordered calls and results, but treat them as a record of attempted activity rather than proof of current state. |
| Incident command | Present one ranked recovery queue and a bounded next action instead of a general activity feed. |
| Chain of custody | Give every claim a stable evidence locator and checksum; package records together without embedding raw private content. |
| Go/no-go gate | A receipt records one explicit process outcome, while a freshness comparison decides whether that observation still applies now. It does not prove what the command semantically tested. |

**Candidate principle:** an interrupted agent session should end with the same three artifacts as a disciplined operational recovery: a reconciled record, a current go/no-go signal, and a handoff whose claims can be independently checked. The transfer is wrong if the inbox becomes a passive history viewer or if a green badge survives repository drift.

## Hard-to-reverse decisions

<Callout id="adapter-contract" tone="decision">
Provider handling becomes an explicit adapter protocol. `discover()` yields provider-neutral `SessionCandidate` metadata; `extract()` yields normalized `TranscriptEvidence`. Public candidate IDs are `ses-` plus a truncated SHA-256 of provider + source session ID, so URLs never expose provider paths and same-looking IDs cannot collide across providers. The existing Claude extractor is wrapped, not silently generalized; Codex ships as `codex-jsonl@1` with fixtures covering `custom_tool_call`, `custom_tool_call_output`, `function_call`, and `function_call_output` call-ID pairing. Before a candidate enters the repository-scoped catalog, its recorded cwd is resolved to a Git root and must equal the owner-selected root; missing, unreadable, or mismatched cwd evidence excludes it rather than guessing from a project name.
</Callout>

<Callout id="path-reconciliation" tone="decision">
Recorded paths may be relative or absolute. An absolute path is accepted only after lexical normalization and canonical resolution prove it is inside the owner-selected repository; it is then converted to a POSIX repository-relative path. Traversal, a leading-dash pathspec, non-POSIX ambiguity, symlink escape, a different worktree, or a nonexistent ancestor that cannot be safely anchored fails closed before Git receives an argument. The selected repository never comes from transcript metadata.
</Callout>

<Callout id="verification-authority" tone="decision">
No transcript-derived command executes, and the web app never executes commands. `agent-ledger verify ... -- ARGV` is the only v1 execution door: the owner supplies argv in the current invocation; the CLI resolves argv[0] once, launches that resolved executable with `shell=False`, `stdin=DEVNULL`, the trusted repository as cwd, the owner invocation's inherited environment with `PWD` corrected, and a new process session. On timeout it terminates the process group, waits a bounded grace period, then kills the group. The receipt stores an explicitly untrusted owner label, executable basename and file digest, argument count and canonical argv digest, exit outcome, duration, and repository fingerprints. It stores neither raw arguments, environment, stdout, nor stderr. UI and prompt templates may render the label only as “Owner label”; it can never become a factual verification claim.
</Callout>

<Callout id="receipt-persistence" tone="decision">
Receipts are not ledger events and do not change the frozen attribution schema. `RecoveryReceipt` v1 is canonical JSON stored as one private file per receipt under `AGENT_LEDGER_DATA_DIR/recovery-receipts/` (defaulting to the platform user-data directory), written atomically with owner-only permissions. Its content-derived ID and component digests provide checksum consistency, not attacker-resistant attestation. Session discovery is immutable for one server run, transcript extraction is lazy and memoized only after a stable source-file digest check, and current Git state is assembled on each selected-session request. Receipt GETs reread the private store and recompute applicability, so “Refresh receipts” works without a server restart; discovering new sessions still requires restart.
</Callout>

<Callout id="package-contract" tone="decision">
`RecoveryPackage` v1 is a single canonical JSON document rather than a ZIP. It embeds the public `RecoveryBrief` and safe continuation prompt, includes the newest receipt attempt for that candidate and brief plus its computed applicability, and carries SHA-256 checksums for each component. Selection never falls back to an older successful attempt: a later failure, error, timeout, or stale attempt governs the handoff state. Package assembly captures one repository fingerprint, assembles all components, then captures it again; drift returns a retryable conflict instead of a mixed-state package. Absolute transcript paths, raw transcript excerpts, raw command argv, command output, environment, capability tokens, and receipt-store paths are prohibited by validation and golden privacy tests.
</Callout>

<Callout id="prompt-boundary" tone="decision">
The continuation prompt has two structurally separate regions: application-authored continuation actions and a length-bounded quoted evidence appendix. Intent, labels, tool names, paths, and transcript statements are untrusted strings; the renderer escapes its sentinels, prefixes every data line, and never interpolates them into imperative templates. Hostile fixtures containing role markers, fake delimiters, shell commands, Markdown links, and “ignore previous instructions” text must remain quoted evidence and produce byte-identical action sections.
</Callout>

<Callout id="repository-fingerprint" tone="decision">
Receipt freshness uses a content-sensitive `RepositoryFingerprint`, not `git status` text. Its canonical digest covers HEAD; `git diff --cached --binary --no-ext-diff`; `git diff --binary --no-ext-diff`; and a sorted manifest of every untracked, non-ignored path with file type, mode, size, and streamed content digest. Symlinks hash their link target without dereferencing; special files, containment failures, Git errors, or configured byte/time limits yield `snapshot_unavailable` and can never produce a current receipt. This detects content drift even when porcelain status stays unchanged.
</Callout>

Receipt freshness is evaluated, not stored as eternal truth:

```text
current = receipt.repository_after.digest == current_repository.digest
       && receipt.brief_digest == selected_brief.digest
```

An exited-zero but stale receipt remains visible as historical evidence and never grants a current state. The latest attempt governs: a later nonzero exit, error, or timeout cannot be hidden by an older exited-zero receipt. The package is always a recovery package, never an independently reproducible attestation; its argv checksum can confirm equality only when the recipient already possesses the command.

CLI surface:

```text
agent-ledger sessions --repo PATH [--provider claude-code|codex]
agent-ledger recover --session CANDIDATE_ID --repo PATH --format json|prompt
agent-ledger console --repo PATH [--session CANDIDATE_ID] [--no-open]
agent-ledger verify --session CANDIDATE_ID --repo PATH --label OWNER_NOTE --timeout SECONDS -- ARGV...
agent-ledger package --session CANDIDATE_ID --repo PATH --output FILE
agent-ledger demo [--no-open] [--smoke]
```

`sessions`, `recover`, `console`, and `package` are read-only. `verify` may run exactly the explicit argv supplied after `--`; it does not edit repository files itself, but the selected command may do so, so the CLI captures repository state both before and after and documents that authority clearly. The owner note is never treated as a description of what the command established.

## Implementation packets

### Packet 1 — adapter seam, Codex evidence, and safe paths

- Introduce the provider-neutral adapter protocol and move Claude-specific discovery behind it without changing `ResumePacket` v1 output.
- Parse Codex envelopes structurally: session metadata for identity/cwd, `custom_tool_call` ↔ `custom_tool_call_output`, and `function_call` ↔ `function_call_output` by call ID. `status: completed` on a call is not a successful tool result.
- Discover a bounded newest-first set with configurable roots and injected clocks/filesystems for deterministic tests.
- Require canonical candidate-to-repository binding before catalog inclusion; mismatched and unbound sessions never assemble against the selected repository.
- Expand path reconciliation to safely normalize repository-contained absolute paths.
- Dogfood against the current Codex rollout using structure-only assertions; never commit or echo its raw content.

Acceptance gate: a sanitized Codex fixture with one unmatched custom call produces `unknown`; a matched result produces the conservative result state; the current rollout is discovered by ID; absolute-in-repo paths normalize; every escape case fails before Git argv; and an agent-ledger candidate is excluded from a recovery-demo console even when its project label looks plausible.

### Packet 2 — Recovery Inbox and selected-session console

- Change `create_app` from one brief to a catalog with immutable startup candidates and internal source locators. Parse transcript evidence lazily after verifying a stable source digest, assemble fresh Git evidence on each selected-session request, and reread receipts on each receipt/package request; expose no rescan or mutation endpoint.
- Preserve the present graphite/warm-paper flight-recorder shell, serif display hierarchy, evidence register, keyboard behavior, and narrow layout. Add an inbox state, provider/readiness filters, selected-session navigation, empty/error states, and a non-JavaScript fallback message.
- Keep rendering text-only through DOM `textContent`; no transcript HTML, external fonts, framework, analytics, or cloud requests.

Acceptance gate: the exact canvas flow works at 1440px and 390px; keyboard-only selection, back navigation, focus restoration, filter state, and status announcements work; existing one-session API tests stay green through compatibility mode.

**Implementation checkpoint (2026-07-18):** catalog and compatibility APIs, lazy digest-checked assembly, the responsive Inbox, filters, selected-session navigation, focus restoration, and redacted error states are implemented. Desktop and 390px rendered checks show no horizontal overflow and no console errors. Semantic keyboard controls and restored focus are present; synthetic Enter-key dispatch in the in-app browser did not activate native buttons, so a physical-keyboard pass remains open before the final Packet 4 UI gate.

### Packet 3 — receipt and package

- Add content-sensitive repository fingerprints over HEAD, staged diff, tracked worktree diff, and untracked content; snapshot inability is an explicit non-current state.
- Add explicit verification process execution, process-group timeout/error handling, before/after fingerprints, receipt validation, atomic private persistence, and freshness evaluation.
- Add canonical package assembly and download headers; select the latest attempt regardless of outcome, retain all local receipt files, and reject concurrent repository drift during assembly.
- Add missing, stale, nonzero, error, and timeout receipt states before the current-exited-zero state so the UI cannot imply a stronger claim than the process result.

Acceptance gate: exit-zero, nonzero, timeout with descendant process, executable-not-found, HEAD drift, same-status tracked-content drift, staged-content drift, untracked-content drift, pass-then-fail precedence, checksum mismatch, recomputed checksum limitation, interrupted atomic write, malicious owner labels, and private-file-permission tests all behave deterministically; no output, raw argv, or environment leaks into receipt, package, API, prompt, or logs.

### Packet 4 — credible demo and handoff

- Extend the synthetic demo with both Claude and Codex fixtures, Inbox → Brief → Missing Receipt → Current Receipt states, and a safe cross-platform verification helper owned by the package rather than a recovered command.
- Add a headless smoke path that starts the server, fetches every protected route, creates a receipt through the CLI execution path, checks freshness, downloads the package, stops, and removes the disposable repository and receipt data directory.
- Update architecture, ADR, README, status, and session evidence. Preserve the existing public BuildWeek evidence boundary and clearly distinguish synthetic demo proof from real local dogfood proof.

Acceptance gate: a built wheel completes the full smoke path from a disposable directory; the real current Codex session produces the same unmatched-call truth signal without any private artifact entering Git.

## Risks and stop rules

<Callout id="risk-command-runner" tone="risk">
**Local command-runner expansion:** if convenience pressure introduces a POST execution route, arbitrary browser argv, recovered transcript commands, or shell invocation, stop. That is a new authority model requiring a separate plan and threat review, not a small UX improvement.
</Callout>

<Callout id="risk-false-green" tone="risk">
**Receipt theatre:** exit code zero is only a process outcome. The UI must mark the owner label as untrusted annotation, show the executable/argument checksum boundary, compare content-sensitive repository state, and say the package is not independently reproducible without the original argv. If a receipt cannot become stale or its label implies what the command established, stop.
</Callout>

<Callout id="risk-provider-drift" tone="risk">
**Provider format drift:** adapters fail closed on unknown event shapes and identify themselves by version. Discovery may still list an unreadable session with an adapter-error status, but extraction never guesses across providers or treats a call's `completed` status as a tool result.
</Callout>

<Callout id="risk-inbox-noise" tone="risk">
**History feed drift:** the Inbox is for recovery decisions, not surveillance or productivity analytics. Cap the list, rank interrupted/unknown sessions first, show only metadata required to choose, and omit message previews, token counts, cost, agent reasoning, and background notifications.
</Callout>

<Callout id="risk-scope" tone="risk">
**Overbuilding:** do not begin another provider, a daemon, cloud sync, account auth, session lineage graph, automatic LLM summary, remote collaboration, or ledger integration until the current Codex dogfood path produces a truthful closed-loop package from the installed wheel.
</Callout>
